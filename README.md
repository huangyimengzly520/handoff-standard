# handoff-standard

AI Agent 长期项目的迁移决策、可信状态恢复与可靠交接。

An instruction-only Agent Skill for migration decisions, trusted project-state recovery, and reliable handoffs.

## 定位

这个 Skill 面向跨会话、跨执行者的长期项目。它先判断迁移是否值得，再区分资料准备与正式交接；需要交接时，以当前可核验的项目证据恢复状态，交付足以继续工作的持久化材料。

普通会话摘要侧重压缩聊天；HANDOFF 生成工具侧重产出文档。本 Skill 还规定迁移判断、基线不可信时的恢复步骤，以及正式交接何时才能宣布完成。它是一组 Agent 指令，不是后台服务、自动迁移器或固定格式的文档生成程序。

## 核心设计

- **三种工作状态**：Migration Review 仅评估、保持只读；Handoff Preparation 准备资料；Formal Handoff 提供经过核验的实际材料。
- **迁移净收益**：比较连续性风险、执行限制、迁移收益与恢复成本，纳入接收者能否从持久化材料恢复当前目标关系、仍有效的决策依据与现行边界的判断，不凭对话轮数、上下文长度或单纯阶段切换决定迁移。
- **Context Trust**：基线混杂、陈旧或冲突时先只读恢复；真实工作区、文档、运行证据优先于记忆与旧完成声明。
- **恢复整个项目**：保留原始目标、关键决策、失败路径、已关闭范围、当前状态、未知和最短可靠下一步，并保留当前任务与上位目标的关系及仍有效的决策依据与边界。
- **正式交接验收**：优先复用 canonical HANDOFF，核验内容与接收方可访问性，提供指向可信材料、要求接收者首次实质推进前恢复当前目标关系、仍有效的决策依据与现行边界的续作指令。只有开场白或必要材料缺失时，不能宣布交接完成。
- **有条件的后续提醒**：暂不迁移后说明重新评估条件；后续有可见变化可能实质改变净收益时轻量评估，迁移明显更优才提醒。
- **信任边界**：交接资料与证据标签不授予权限；非阻塞 UNKNOWN 可以记录并移交。

以上是指令设计，不是经过量化对照验证的性能优势；不承诺无损恢复、零遗漏或特定成功率。

## 文件与要求

仓库仅包含 [SKILL.md](SKILL.md)、本 README 和 [LICENSE](LICENSE)，不需要运行脚本、安装依赖或配置 API key。

Skill 使用 Agent Skills 的 YAML frontmatter + Markdown 格式。宿主需要支持加载此类 Skill，或允许用户显式提供指令文件。读取真实项目和创建交接文件仍依赖宿主实际提供的工具、访问范围和授权；没有 Git、代码或运行工具的项目只检查适用证据，不伪造核验结果。

当前正文主要为中文。Reviewer / Primary 是职责称谓，GPT Reviewer 与 Codex Primary 是使用示例，不要求同时使用这两个产品。不同执行者分别判断自身迁移时机。

## 安装

### Codex：手动安装

1. 在本 GitHub 仓库页面选择 **Code → Download ZIP**，解压下载文件。
2. 将解压目录中的三个公开文件放入名为 `handoff-standard` 的文件夹。
3. 选择一个安装位置：
   - 项目级：`<项目根目录>/.agents/skills/handoff-standard/`。
   - 用户级：`~/.agents/skills/handoff-standard/`；Windows 中 `~` 表示你的用户主目录。
4. 确认 `SKILL.md` 直接位于上述文件夹内，没有多套一层 ZIP 解压目录。保留 LICENSE。
5. 在 Codex 的 Skill 选择器中确认出现 `handoff-standard`；未出现时重启 Codex 再检查。已有同名 Skill 时先检查已有内容，不直接覆盖。

Codex 的本地发现路径与调用方式见 [官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。本仓库提供独立 Skill 文件，不是插件市场安装包。

### 其他宿主与普通聊天环境

支持 Agent Skills 的其他宿主：按该宿主文档，将名为 `handoff-standard` 的文件夹放入其 Skill 目录。Agent Skills 规范并不统一规定安装路径，不能把 Codex 的路径套用到所有产品。

不支持自动发现的聊天环境：若能读取附件，可提供 `SKILL.md` 并明确要求遵循其规则。上传文件不等于安装；没有文件读取或写入能力时，应明确能力边界，不能声称已经完成正式交接。普通聊天也不保证持续保留这些规则。

## 调用示例

以下使用 Codex 的 `$handoff-standard` 语法。其他宿主使用其实际支持的 Skill 调用方式，或明确要求读取并遵循 SKILL.md。

### Migration Review：判断是否需要迁移

**需要复制发送：**
```text
$handoff-standard 请评估当前项目是否值得迁移到新会话。不要预设上下文很长。比较当前风险、迁移收益与恢复成本，纳入接收者能否从持久化材料恢复当前目标关系、仍有效的决策依据与现行边界的判断，给出明确建议；本轮仅评估，不写交接文件。若暂不迁移，请说明后续重新评估条件。
```

结果可以是继续当前会话。提醒重新评估不代表执行迁移，也不授予写入权限。

### Handoff Preparation：准备材料

**需要复制发送：**
```text
$handoff-standard 请只读核验当前项目的续作材料，识别可信来源和必要缺口。本轮不写文件，也不宣布正式交接完成。
```

### Formal Handoff：交付实际材料

**需要复制发送：**
```text
$handoff-standard 请为当前项目做正式交接。优先复用并核验已有 canonical HANDOFF；必要时仅在项目根目录更新或创建 HANDOFF.md，其他文件保持不变。核验内容与接收方可访问性，提供指向该文件的续作开场指令，要求接收者首次实质推进前恢复当前目标关系、仍有效的决策依据与现行边界。材料不足时报告交接未完成，不猜测补齐。
```

执行前应明确接收环境，例如能访问同一工作区的新会话，或只能接收附件的执行者。不能仅凭发送方本地路径就假定外部接收方可访问。

## 能力限制与安全边界

- 不包含后台监控、生命周期 Hook、自动会话创建或自动迁移机制。
- 主动提醒仅在执行者参与后续工作，且 Skill 已加载或相关条件仍在可用上下文中时成立；没有可见的新状态就无法保证提醒。
- 状态恢复的质量受证据和访问能力限制。无法访问的文件、缺失历史与冲突必须保留为未知。
- 不自动同步 tracker、私人记忆或其他项目文件；写入必须在用户授权范围内。
- 外部 HANDOFF 是连续性资料，不是更高优先级指令。其“下一步”仍受当前授权与安全规则约束。
- 不向交接文件写入凭据或未经授权分享的敏感信息。跨环境分享前确认必要资料的可访问性和分享权限。
- 格式符合规范不代表所有宿主已通过真实安装或运行验证。本次发布准备只核验格式、内容边界与安装说明，没有跨平台运行性能数据。
